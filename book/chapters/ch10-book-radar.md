# 第 10 章　新書雷達：比較書單，找出新上架書籍

「新書」在程式裡必須有可檢查的定義。本章採用「相較上一次成功取得的完整書單，第一次出現的詳細頁 URL」作為新增。它不是出版日期，也不保證網站第一次列出的日期就是實際上架日。

## 本章目標

完成後，你能建立可信基準、找出新增與消失的書目，並在查詢失敗時保留舊基準。

## 執行前準備

需要第 9 章的書單概念與可寫入的輸出目錄；首次執行會建立自己的基準檔。

## 10.1　先建立可信基準

第一次執行 E12 沒有 `baseline.json`，程式只保存完整清單，報告顯示建立基準。第二次執行才進行集合差集：

```python
old_urls = {book["url"] for book in previous}
new_books = [book for book in current if book["url"] not in old_urls]
```

使用網址而不是標題，可以保留同名不同頁的書；書名修改但網址不變，則不會被誤判為新書。這是資料模型的選擇，應在報告中寫清楚。

## 10.2　成功才更新基準

執行：

```bash
.venv/bin/python examples/04_tracking/happyebook_new_books.py
```

E12 會先確認完整書單、連結有效且不重複，再將本次清單寫入 `outputs/books/radar/baseline.json`。任何檢查失敗都保留舊基準，避免一次網路錯誤破壞下次比較。

第一次執行的輸出類似：

```text
首次執行，已建立 226 筆書目的基準；下次會比較新增書籍。
```

第二次執行會改成「完整書單 N 筆；新增 M 筆」，其中 `N`、`M` 依當天網站內容變化。

報告包含 `latest.json`、`latest.html` 和 `history/` 快照。第一次報告可以列出全部書單，卻要明確標示「首次建立基準」，不能標成新增。

## 10.3　處理刪除和重新出現

如果上次有甲、乙，本次只有甲，乙會列為「本次未再出現」；如果第三次乙重新出現，依目前基準它會再次成為新增。這不代表乙真的重新上架，也可能是網站暫時篩選或連結改變。報告保留未再出現項目，讓讀者能判斷資料變化。

同一輸出目錄只能由一個程序更新。若同時啟動兩個雷達，可能互相覆蓋基準；需要排程時，使用工作排程器的單一工作或檔案鎖。

## 10.4　用固定資料練習

外站書單每天不同，先用專案 `tests/python/fixtures/radar-before.json` 和 `radar-after.json` 練習集合差集；它們示範從甲、乙增加丙。完成後再連線 Happy eBook。這能把「差集邏輯」和「網站定位失敗」分開除錯。

## 10.5　練習

1. 執行兩次 E12，描述第一次和第二次報告的差異。
2. 只改書名不改 URL，確認不會算新增；再改 URL，觀察結果。
3. 備份 `baseline.json` 後暫時改壞 JSON，確認程式拒絕覆寫並顯示錯誤。

完成條件是你能說明「新增」的定義，能找到基準檔和歷史報告，並知道一次失敗不應清空上次資料。下一章把同樣的日期、去重和報告觀念應用到 AI 新聞。
