# 第 16 章　活動報名提醒：偵測狀態變化與避免重複通知

活動提醒的目標是知道「報名入口是否出現」，不是替讀者自動送出報名資料。這個界線讓程式保持唯讀，也避免在名額、費用或個人資料未確認時做出不可逆操作。

## 16.1　把狀態定義清楚

E11 接受活動 URL、報名按鈕選擇器和按鈕文字。狀態可分為 `open`、`closed`、`missing`、`error`：看見「下一步」或「立即報名」才算入口開放；頁面顯示額滿或截止是關閉；找不到元素是網站改版或選擇器錯誤，不能直接算關閉。

一次檢查：

```bash
.venv/bin/python examples/04_tracking/event_registration_watch.py \
  'https://example.com/event' \
  --selector '#register-button' --open-text '立即報名' --name '我的活動'
```

程式會保存狀態 JSON 和 `alerts.jsonl`。第一次只建立基準；狀態由關閉變開放時才通知，避免每五分鐘重複提醒。

## 16.2　選擇器和按鈕文字

活動網站的 class、按鈕文字和報名期限都可能改變。選擇器應由讀者在有畫面模式或開發者工具確認；`--open-text` 要填頁面實際顯示的文字。若按鈕存在但文字是「下一步」，它和「立即報名」是不同的契約。

程式只檢查入口，不點擊下一步、不填寫姓名、不送出表單。通知內容包含活動名稱、狀態、查詢時間和 URL，讓讀者自己判斷是否報名。

## 16.3　定期執行

```bash
.venv/bin/python examples/04_tracking/event_registration_watch.py \
  'https://example.com/event' --selector '#register-button' \
  --open-text '立即報名' --watch --interval 300 --count 12
```

可用作業系統排程器取代長時間 `--watch`。每次執行都應使用同一個輸出目錄，否則程式讀不到上一個狀態。活動結束或網址失效後，清理對應狀態檔前先保存通知紀錄。

## 16.4　通知限制

Linux 桌面嘗試使用 `notify-send`，不可用時退回終端機提示。這不是雲端推播；電腦關機時不會檢查。若要寄信、發訊息或使用行動通知，需要另外設計憑證、錯誤重試和個資保護。

## 16.5　練習

1. 用本機 HTML 建立「截止」和「立即報名」兩種狀態，測試第一次與狀態變化通知。
2. 將選擇器故意改錯，確認結果是 `error` 或明確失敗，而不是 `closed`。
3. 為通知加入活動期限，期限後停止排程。

下一篇會把已學的瀏覽器操作用於內容發布；那幾個範例會改動外部網站，必須先讀懂確認流程。
