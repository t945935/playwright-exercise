# 第 15 章　台積電股價追蹤：保存歷史、比較漲跌與產生報表

排行榜回答「現在誰漲最多」；追蹤器回答「台積電這次和上一次有效紀錄差多少」。兩者都需要正確價格，但比較基準不同。

## 15.1　只接受有效成交價

E10 查詢證交所台積電（2330）的行情，優先使用正式成交價 `z`；若快照沒有成交價，才使用來源提供的上一筆正式成交 `trade.z`。不以委買、委賣、昨收或試撮價冒充成交價。

```bash
.venv/bin/python examples/04_tracking/tsmc_price_tracker.py
```

第一次有效執行只建立基準。後續執行讀取 SQLite 中上一筆有效紀錄，計算價格差和百分比。這和拿昨收比較是不同功能，報告應直接寫出比較的是「上一次成功保存的成交價」。

## 15.2　SQLite 的最小結構

資料庫至少保存查詢時間、行情時間、價格、來源和比較狀態。行情時間是來源告訴你的交易時間；查詢時間是你的程式何時收到資料。兩者都保留，才能發現資料延遲或重複。

同一行情時間不重複寫入。`UNIQUE` 約束或寫入前查詢都可以做到；遇到重複時顯示「已存在」，不要把它算成持平的新紀錄。

## 15.3　報告和持續監看

```bash
.venv/bin/python examples/04_tracking/tsmc_price_tracker.py --watch --interval 60 --count 5
```

`--watch` 每隔一段時間查詢，休市時顯示原因並繼續等待。CSV 適合試算表，HTML 報告適合瀏覽器；SQLite 是下次執行真正需要保留的基礎資料。不要用 HTML 顏色判斷資料，顏色只是呈現。

綠色代表價格下降、紅色代表上升只是本範例的報告慣例；讀者應查看數字和比較時間，不能把顏色當投資建議。

## 15.4　資料品質情境

盤前、休市、舊日期、兩處都缺價時不新增紀錄。外部 API 回應成功不等於行情有效；先檢查欄位、日期和行情類型，再保存。遇到來源格式改版，保留原始錯誤資訊供更新程式。

## 15.5　練習

1. 第一次執行後查看 SQLite 表格，再執行一次比較兩筆紀錄。
2. 使用 `--output-dir /tmp/tsmc-demo` 建立獨立資料庫，確認不影響原本歷史。
3. 用固定價格資料測試上漲、下跌、持平和重複行情四種情況。

下一章將把「保存上次狀態」用在活動報名入口，偵測按鈕何時從關閉變為可報名。
